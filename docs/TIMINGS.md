# Калібрування таймінгів / Timing calibration

Аудит операційних таймінгів скан/remote-підсистеми (2026-09-07). Внутрішні таймінги
окремих builtin-застосунків (battery_diag, clock тощо) сюди не входять — лише те, що
впливає на зв'язок плата↔додаток↔сервер і на радіо-скани.

## nRF24 2.4G scan (відкалібровано наживо)

| Параметр | Значення | Обґрунтування |
|---|---|---|
| SPI clock | **8 МГц** (тюн. `?hz=`, стеля 10 МГц) | свіп 1..10 МГц = 12/12 на всіх; 8 = margin |
| dwell / канал | **300 µs** (тюн. `nrf24_set_dwell_us`) | живий свіп: 300µs = 21.7 актив.каналів@305мс — оптимум |
| проходів (passes) | 6 | ~305 мс сумарно; акумулює темпоральне покриття бурстів |

**Живий свіп dwell** (`/api/nrf/spectrum?diag=1&dwell=N`): 150µs=8ch (PLL не осів),
**300µs=21.7ch**, 500µs=12.7, 800µs=16.7, 1200µs=18.3. Довший dwell НЕ покращує — RPD
миттєвий фіксатор носійної, не інтегратор; для «глибшого» скану збільшувати passes, не dwell.

## Rate-limit сканів (плата)

| Скан | Ліміт | Нотатка |
|---|---|---|
| airscan | **7 с** throttle (`s_last_air`) | часті скани вузлять STA-несучу (radio wedge) |
| netscan / devscan | без throttle | ARP/порти не чіпають радіо |

## Поллінг додатка

| Цикл | Інтервал | Джерело |
|---|---|---|
| status (плата) | USB 1с · WiFi 3с · busy 1.5с · gateway 4с | `startPolling` |
| «плата зайнята» | 2 невдалі поспіль | `fails>=2 -> linkBusy` |
| розрив зв'язку | 12 невдалих (~18 с) + гасіння live-сканів | `fails>=12` |
| airscan live | 12 с | > board throttle 7 с (не ловить throttle) |
| netscan live | 20 с | |
| log poll | 1.5 с (лише WiFi; USB стрімить) | |
| server poll | 8 с (незалежно від плати) | `startServerPoll` |
| admin server refresh | 6 с | `AdminScreens` |

**Когерентність:** live-airscan 12с > board-throttle 7с ✓; poll використовує легкий
`/api/status`, не scan-throttle ✓; розрив ~18с гасить live-скани → нуль шансів повторно
ронити плату на реконекті ✓.

## Loop плати (main.cpp)

| Задача | Період |
|---|---|
| status-push (authed) | 2 с |
| охолодження (temp→PWM) | 2 с |
| flush логу на SD | 2 с |
| HMAC nonce TTL | 60 с |

**Висновок аудиту:** таймінги вже узгоджені; змін не потребували. nRF-dwell перевірено
емпірично (300µs підтверджено оптимальним). Додано рантайм-тюнінг `?hz=`/`?dwell=` для
майбутніх замірів без перепрошивки.
